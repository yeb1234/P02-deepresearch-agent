# 模型配置说明

## 如何添加/修改可用模型

### 方法：修改 .env 配置文件

编辑 `backend/.env` 文件中的 `AVAILABLE_MODELS` 环境变量，并用 `DEFAULT_MODEL_ID` 明确默认模型。

### 配置格式

```env
AVAILABLE_MODELS=[{"model_id":"模型ID","display_name":"显示名称","icon":"图标类型","icon_color":"颜色类名","is_default":false}]
DEFAULT_MODEL_ID=默认模型ID
```

**字段说明：**
- `model_id`: 实际调用LLM时使用的模型标识
- `display_name`: 前端下拉框显示的名称
- `icon`: 图标类型，可选 `Zap`（闪电）或 `Cpu`（芯片）
- `icon_color`: 图标颜色，使用 Tailwind CSS 颜色类名
- `is_default`: 可选，标记默认模型；`DEFAULT_MODEL_ID` 优先级更高
- `DEFAULT_MODEL_ID`: 可选的显式默认模型，必须出现在 `AVAILABLE_MODELS` 中

### 研究深度与模型思考的边界

- 前端只暴露一个“研究深度”下拉，避免用户同时面对“检索深度”和“思考深度”两套叫法。
- 研究深度同时决定检索规模和模型思考档位：
  - 仅搜索：2 条查询 / 1 轮检索，跳过计划、提纲、初稿、审稿和润色，直接生成简短问答；模型思考关闭；
  - 快速：1 条查询 / 1 轮研究，模型思考关闭；
  - 标准：3 条查询 / 3 轮研究，模型思考标准；
  - 深入：5 条查询 / 10 轮研究，模型思考深入。
- 后端按模型厂商自动换算，不把厂商原始档位暴露给用户：
  - Qwen 系：关闭 → `enable_thinking=false`；标准 → `reasoning_effort=high`；深入 → `reasoning_effort=xhigh`。
  - DeepSeek V4 系：关闭 → `thinking={"type":"disabled"}`；标准 → `reasoning_effort=high`；深入 → `reasoning_effort=max`。
  - 不认识的 OpenAI 兼容模型：关闭 → `enable_thinking=false`；开启时发送标准 `reasoning_effort`。
- 任务级选择通过 `thinking_level` 传入，使用 `ContextVar` 隔离，避免并发任务互相覆盖；API 调用方仍可显式传 `thinking_level`，未传时默认 `off`。

### 搜索中间层模型

搜索链路和最终写作模型解耦：

- 查询生成、MCP 搜索结果摘要默认使用 `SEARCH_SUMMARY_MODEL=qwen3.8-flash`；
- 用户选择的 `reasoning_model` 只负责反思评估、提纲、写作和审稿；
- 实测同一批 MCP 结果（最新提示词收紧后）：
  - Qwen-Plus：查询生成 5.0s、摘要 7.4s，摘要保留 5/7 个链接；
  - Qwen3.8-Flash：查询生成 3.4s、摘要 5.5s，摘要保留 6/7 个链接；
  - DeepSeek V4.1 Flash：查询生成 1.5s、摘要 2.7s，摘要保留 7/7 个链接，但单价更高。
- 因此默认中间层用 Qwen3.8-Flash 平衡速度、链接保留和成本；需要更强摘要时可将 `SEARCH_SUMMARY_MODEL` 改为 `deepseek-v4.1-flash`。
- 评审/评估模型单独配置为 `REVIEW_MODEL=deepseek-v4.1-flash`：反思评估和初稿评审走 DeepSeek，常规生成、提纲、写作、润色仍用用户选择的 Qwen（默认 Qwen-Plus）。
- 仅搜索模式同样遵守上述路由：查询生成与摘要 `qwen3.8-flash`，一轮反思 `deepseek-v4.1-flash`，简短回答使用用户选择的 `reasoning_model`（默认 `qwen-plus-latest`）；实测 610 字、4 个可点击来源。
- 1 轮端到端实测：查询生成与摘要为 `qwen3.8-flash`，反思评估 `deepseek-v4.1-flash`，提纲/初稿/润色 `qwen-plus-latest`，初稿评审 `deepseek-v4.1-flash`；评审 8.5/10 进入润色，最终 2626 字、5 个来源。
- 2026-11-17 端到端实跑（Qwen-Plus + 快速、2 轮检索）：首轮 MCP 8→7 条、次轮 10→8 条；查询生成为 2 条短中文查询，反思后补 2 条；最终完成 10208 字报告、15 个来源。说明查询、检索、归一化、摘要、反思、写作链路已打通。
- 单次 LLM 请求已加 `LLM_REQUEST_TIMEOUT=240` 秒上限，避免某个模型调用无限挂起；研究轮数、首轮查询数也会写入图初始状态，确保前端“研究深度”设置生效。
- 最新 1 轮端到端验收：图表状态为 2 条初始查询、1 轮检索、直接进入提纲/写作/润色；最终 4763 字、24 个可点击链接、0 个 `search.com` 占位符、0 个裸编号引用。
- DeepSeek V4.1 Flash 在反思阶段曾因输出注释式 JSON 触发一次解析重试；已在反思/查询提示词中要求合法 JSON、禁止注释和未转义英文双引号。

搜索结果进入模型前会做归一化：只保留 http(s) 链接、去掉跟踪参数、统一移动站域名、按 URL/标题/正文相似度去重，并限制条数、单条 snippet 和总字符预算。相关实现见 `backend/src/agent/search_normalizer.py`。

### 当前模型与价格

以下是 2026-11 百炼官方页面展示的按量单价（元 / 百万 tokens，非思考模式，未计限时优惠）：

| 显示名称 | model_id | 输入 | 输出 | 说明 |
|---|---|---:|---:|---|
| Qwen-Plus | `qwen-plus-latest` | 0.8 | 2.0 | 当前默认；非思考模式输出 2.0，思考模式输出 8.0 |
| Qwen3.8-Flash | `qwen3.8-flash` | 0.8 | 2.7 | 缓存命中输入 0.1 |
| DeepSeek V4.1 Flash | `deepseek-v4.1-flash` | 忙时 2 / 闲时 1 | 忙时 8 / 闲时 4 | 闲时 22:00–08:00 |

按上述单价，`Qwen-Plus` 在非思考模式下输出单价最低，因此被设为默认。项目通过 `LLM_THINKING_LEVEL=off` 把默认思考深度设为关闭，并在请求层按厂商发参：Qwen 发 `enable_thinking=false`，DeepSeek 发 `thinking={"type":"disabled"}`。如果打开思考模式，Qwen-Plus 的输出单价会升到 8 元/百万 tokens，成本会高于 Flash 系列。

参考：[qwen-plus 价格](https://help.aliyun.com/zh/model-studio/qwen-plus)、[qwen3.8-flash 价格](https://help.aliyun.com/zh/model-studio/qwen3-8-flash)、[deepseek-v4.1-flash 价格](https://help.aliyun.com/zh/model-studio/deepseek-v4-1-flash)。实际账单以百炼控制台为准。

### 示例：添加新模型

在 `.env` 文件中添加或修改：

```env
AVAILABLE_MODELS=[{"model_id":"qwen-plus-latest","display_name":"Qwen-Plus","icon":"Zap","icon_color":"orange-400","is_default":true},{"model_id":"qwen3.8-flash","display_name":"Qwen3.8-Flash","icon":"Zap","icon_color":"yellow-400"},{"model_id":"deepseek-v4.1-flash","display_name":"DeepSeek V4.1 Flash","icon":"Zap","icon_color":"blue-400"}]
DEFAULT_MODEL_ID=qwen-plus-latest
```

**范例：**
```json
[
  {"model_id":"qwen-plus-latest","display_name":"Qwen-Plus","icon":"Zap","icon_color":"orange-400","is_default":true},
  {"model_id":"qwen3.8-flash","display_name":"Qwen3.8-Flash","icon":"Zap","icon_color":"yellow-400"},
  {"model_id":"deepseek-v4.1-flash","display_name":"DeepSeek V4.1 Flash","icon":"Zap","icon_color":"blue-400"}
]
```

### 图标选项

- **Zap**: 闪电图标（适合快速模型）
- **Cpu**: 芯片图标（适合强大模型）

### 颜色选项

使用 Tailwind CSS 颜色类，例如：
- `yellow-400`, `orange-400`, `red-400`
- `green-400`, `blue-400`, `purple-400`
- `pink-400`, `indigo-400`, `teal-400`

### 生效步骤

1. 修改 `backend/.env` 文件中的 `AVAILABLE_MODELS` 和 `DEFAULT_MODEL_ID`
2. 重启后端服务
3. 刷新前端页面，模型列表和默认选项自动更新

### 注意事项

- JSON 格式必须正确，注意引号和逗号
- 确保 `model_id` 与后端 LLM 服务支持的模型名称一致
- 如果未配置 `AVAILABLE_MODELS` 或格式错误，系统会使用内置的 Qwen-Plus / Qwen3.8-Flash / DeepSeek V4.1 Flash 列表
- 后端会把客户端传入的 `reasoning_model` 收敛到 `AVAILABLE_MODELS` 白名单；未传或拼写错误会回退到默认模型
- 修改后无需重新编译前端代码
- 前端会在 API 请求失败时使用同一份兜底模型列表，并以 `is_default` 选择默认，不依赖数组顺序
